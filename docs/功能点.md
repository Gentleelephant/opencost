# CostWize 页面功能点梳理

> 本文档梳理每个页面的功能点，对应 API 及字段。
>
> 对应设计图路径：`docs/png/`
>
> **核心 API：** `GET /kapis/costwise.wiztelemetry.io/v1alpha1/allocation`（覆盖 95% 功能点）
>
> API 基础地址：`http://<部署地址>:32578/kapis/costwise.wiztelemetry.io/v1alpha1`
>
> **通用参数说明：**
> - `window=7d` — 时间窗口（支持 `1d`/`7d`/`30d`/`自定义起始,结束`）
> - `aggregate=<维度>` — 聚合维度，必选
> - `filter=<字段>:"<值>"` — 过滤，引号需 URL 编码为 `%22`
>
> **时间粒度控制（3 个参数的区别）：**
> - `accumulate=true` — 将窗口内所有数据汇总为 **1 条**，适用于卡片展示总成本
> - `step=1d` — 按天拆分为 **N 条**时间序列，适用于趋势折线图
> - `accumulateBy=day|week|month` — 在 step 拆分的基础上，按指定粒度**重汇总**
>
> **实测对比（window=3d, host集群）：**
> ```
> // ① 不加任何参数 → 默认 1 条（整个窗口）
> GET /kapis/costwise.wiztelemetry.io/v1alpha1/allocation?window=3d&aggregate=cluster
> 返回: [2026-05-10 ~ 2026-05-13]  总成本=232705.99
>
> // ② accumulate=true → 合并为 1 条（适用于汇总卡片）
> GET /kapis/costwise.wiztelemetry.io/v1alpha1/allocation?window=3d&accumulate=true&aggregate=cluster
> 返回: [2026-05-10 ~ 2026-05-13]  总成本=232705.99  (1条)
>
> // ③ step=1d → 按天拆成 3 条（适用于趋势折线图）
> GET /kapis/costwise.wiztelemetry.io/v1alpha1/allocation?window=3d&step=1d&aggregate=cluster
> 返回: [5/10~5/11] 总成本=0     ← 这条跨了2天但值=0
>       [5/11~5/12] 总成本=206849.75
>       [5/12~5/13] 总成本=25856.24
>
> // ④ step=1d + accumulateBy=week → 先拆天再合周
> GET /kapis/costwise.wiztelemetry.io/v1alpha1/allocation?window=7d&step=1d&accumulateBy=week&aggregate=cluster
> 返回: [5/11~5/13] 总成本=232705.99  (按自然周合并后剩1条)
>
> // ⑤ accumulateBy=all → 等价于 accumulate=true
> GET /kapis/costwise.wiztelemetry.io/v1alpha1/allocation?window=3d&accumulateBy=all&aggregate=cluster
> 返回: [2026-05-10 ~ 2026-05-13]  总成本=232705.99  (1条)
> ```
>
> **一句话总结：**
> | 你要做什么 | 用什么参数 | 返回条数 |
> |-----------|-----------|---------|
> | 汇总卡片（单集群总成本） | `accumulate=true` | 1 条/集群 |
> | 汇总卡片（所有集群合计） | `accumulate=true&aggregate=cluster`，前端对各集群 totalCost 求和 | 每条对应一个集群 |
> | 趋势折线图（每天一个点） | `step=1d` | N 条（按天拆分） |
> | 按周显示趋势 | `step=1d&accumulateBy=week` | 按自然周合并 |
> | 按月显示趋势 | `step=1d&accumulateBy=month` | 按自然月合并 |
>
> **跨集群合计规则：** API 不提供"合并所有集群"的聚合参数。需要展示多集群总和时，用 `aggregate=cluster` 拿到每个集群的数据，前端自行求和。效率同理，使用成本加权平均：`Σ(cluster.totalCost × cluster.totalEfficiency) / Σ(cluster.totalCost)`。
>
> **filter 支持的字段：** `cluster` ✅ `namespace` ✅ `node` ✅ `pod` ✅ `container` ✅
> **filter 不支持的字段：** `deployment` ❌ `controller` ❌ `service` ❌ `label:<key>` ❌ `namespaceLabels.xxx` ❌
> 对于不支持的 filter，替代方案是前端从已返回数据中过滤

## 核心计算定义（参考 OpenCost 官方规范）

> 来源：https://opencost.io/docs/specification#foundational-definitions

### 成本分类层次
```
集群总成本 = 集群资产成本 + 集群附加成本
           ↓
           工作负载成本 + 集群空闲成本 + 集群附加成本
```
其中：
- **集群资产成本** = 各项资源（CPU/RAM/GPU/PV/网络/LB）成本之和
- **集群附加成本** = 集群管理费 + 运维人工分摊等
- **工作负载成本** = 工作负载实际产生的成本
- **空闲成本** = 已分配但未使用的资源成本

### WorkloadCost = max(request, usage) — "取大原则"
这是 OpenCost 最核心的计算规则：

```
工作负载成本 = max(已申请量, 实际使用量) × 单价 × 时长
```

对于分配型资源（CPU、GPU、RAM），成本按 **申请量和使用量中的较大值** 计算。如果 Pod 申请了 4 核 CPU 但只用 0.5 核，账单按 4 核计算。

### 资源效率（Efficiency）

```
CPU 效率   = cpuCoreUsageAverage / cpuCoreRequestAverage
            → 实际使用 / 申请量

内存效率   = ramByteUsageAverage / ramByteRequestAverage
            → 实际使用 / 申请量

综合效率   = (cpuCost × cpuEfficiency + ramCost × ramEfficiency)
            / (cpuCost + ramCost)
            → 按成本加权的平均效率

等效公式：  效率 = 1 - 空闲率
           资源效率 = 工作负载成本 / (空闲成本 + 工作负载成本)
```
- 效率 > 1：使用量超过申请量，建议显示封顶 100%
- 纯按用量计费的资源（如某些网络费），效率固定为 100%

### 空闲成本（Idle Cost）

```
集群空闲成本 = 集群资产成本 - 工作负载成本
集群空闲率   = 空闲成本 / 资源分配成本

资源空闲量   = 申请量 - 使用量（当申请量 > 使用量时）
```
空闲成本衡量的是"你付了钱但没用上的资源"。

### 月度费率

```
月度费率 = totalCost × (730 × 60 / minutes)
```
将当前窗口的成本推算到整月（730 小时/月）。如果数据不足整月，此值为估算值。

### 共享成本分摊

三种分摊方式（spec 定义）：
1. **均匀分摊**：在所有租户间平均分配
2. **按比例分摊**：按租户的资产成本占比分配
3. **自定义指标**：按网络出站流量等自定义规则

### 顶部汇总卡片

- **总成本（集群维度），及较上周期百分比变化**
  → `GET /kapis/costwise.wiztelemetry.io/v1alpha1/allocation?window=7d&accumulate=true&aggregate=cluster`（默认窗口）
  → 字段：`.data[0]["host"].totalCost`（单集群）或各集群 `.totalCost` 求和（多集群）
  → 多集群示例：`aggregate=cluster` 返回 `17-4: 0.04, host: 25856.24`，合计 = 25856.29
  → **日环比（2 次 1d 请求）：**
    ```
    // 请求1 — 今天
    GET /allocation?window=2026-05-12T00:00:00Z,2026-05-13T00:00:00Z&accumulate=true&aggregate=cluster
    → totalCost_today = 20110.45

    // 请求2 — 昨天（window 向前平移 1 天）
    GET /allocation?window=2026-05-11T00:00:00Z,2026-05-12T00:00:00Z&accumulate=true&aggregate=cluster
    → totalCost_yesterday = 206849.75

    // 计算
    变化率 = (20110.45 - 206849.75) / 206849.75 × 100 = -90.28%
    ```
  → **周环比（2 次 7d 请求）：**
    ```
    // 请求1 — 近 7 天
    GET /allocation?window=2026-05-06T00:00:00Z,2026-05-13T00:00:00Z&accumulate=true&aggregate=cluster
    → totalCost_thisWeek = 232705.99

    // 请求2 — 上 7 天（window 向前平移 7 天）
    GET /allocation?window=2026-04-29T00:00:00Z,2026-05-06T00:00:00Z&accumulate=true&aggregate=cluster
    → totalCost_lastWeek = 200000.00  (假设值)

    // 计算
    变化率 = (232705.99 - 200000.00) / 200000.00 × 100 = +16.35%
    ```
  → **通用公式：** `(当期值 - 上期值) / |上期值| × 100`，`window` 时间范围前后平移即得上期
  → 正值为增长(↑)，负值为下降(↓)

- **集群综合效率（百分比），及较上周期百分比变化**
  → `GET /kapis/costwise.wiztelemetry.io/v1alpha1/allocation?window=7d&accumulate=true&aggregate=cluster`（默认窗口）
  → 字段：`.data[0]["host"].totalEfficiency`（0~1，显示时 ×100 + "%"）
  → **日环比（2 次 1d 请求）：**

    变化率 = (0.2000 - 0.1497) / 0.1497 × 100 = +33.60%  (假设今天为0.20)
    ```
  → **周环比（2 次 7d 请求）：**
    ```
    GET /allocation?window=2026-05-06T00:00:00Z,2026-05-13T00:00:00Z&accumulate=true&aggregate=cluster

- **各效率项的类型：CPU 效率、内存效率、存储(PV)效率**
  → 同集群维度请求
  → 字段：`.cpuEfficiency`、`.ramEfficiency`
  → PV/存储效率：OpenCost 标准中存储按容量计费（`PV 容量 × 单价`），不同于 CPU/内存的 usage/request 效率模型，建议直接展示存储总成本 `.pvCost` 而非效率百分比

  - **资源级成本详情：CPU 的使用成本（usage）、分配成本（allocation）、空闲成本（idle）**
    → 三个概念的关系：**allocation = usage + idle**
    → **分配成本（allocation）**：`/allocation?accumulate=true&aggregate=cluster` → `.cpuCost`
    → **使用成本（usage）**：`cpuEfficiency × cpuCost`
    → **空闲成本（idle）**：`(1 - cpuEfficiency) × cpuCost` = cpuCost - usage
    → 验证：`usage + idle = cpuEfficiency × cpuCost + (1 - cpuEfficiency) × cpuCost = cpuCost`
    → **说明：** `cpuCostIdle` 当前始终为 0（后端未启用 SplitIdle），因此公式中无需处理它。
      如果后端启用了 `includeIdle=true&shareIdle=true`，则公式变为：
      `usage = cpuEfficiency × (cpuCost - cpuCostIdle)`
      `idle  = (1 - cpuEfficiency) × (cpuCost - cpuCostIdle) + cpuCostIdle`
      其中 `cpuCostIdle` 是资产侧的空闲分摊部分（infra idle）。

  - **资源级成本详情：内存（RAM）的使用成本（usage）、分配成本（allocation）、空闲成本（idle）**
    → **分配成本（allocation）**：`/allocation?accumulate=true&aggregate=cluster` → `.ramCost`
    → **使用成本（usage）**：`ramEfficiency × ramCost`
    → **空闲成本（idle）**：`(1 - ramEfficiency) × ramCost`
    → 规则完全同 CPU

  - **资源级成本详情：存储（PV）的使用成本（usage）、分配成本（allocation）、空闲成本（idle）**
    → **分配成本（allocation）** = **使用成本（usage）** = `/allocation` → `.pvCost`
    → **空闲成本（idle）**：存储按容量计费（`PV 容量 × 单价`），没有 usage/request 模型，因此 idle = 0
    → **注意：** API 无 `pvCostIdle` 字段；如需存储空闲分摊需从资产侧推算

  - **资源级汇总总览（usage / allocation / idle）**
    → 效率 API 已按此口径返回汇总值，前端直接取用即可：
    ```
    GET /efficiency/clusters/summary?window=7d&accumulate=true

    ① 顶层总计字段：
    → totalUsageCost    = usage 合计（CPU+RAM+GPU）
    → totalAllocationCost = allocation 合计
    → totalIdleCost    = idle 合计 = resourceCost - usageCost
    → workloadIdleCost = workload 内部空闲（request未用完部分）
    → infraIdleCost    = 基础设施空闲（当前=0，因 cpuCostIdle=0）

    ② 单资源 breakdown（每个集群和 summary 都有）：
    → cpu.allocation / cpu.usage / cpu.idle / cpu.efficiency   ← CPU
    → ram.allocation / ram.usage / ram.idle / ram.efficiency   ← 内存
    → gpu.allocation / gpu.usage / gpu.idle / gpu.efficiency   ← GPU
    → pv.allocation / pv.usage / pv.idle / pv.efficiency      ← 存储（usage=allocation, idle=0）

    ③ 多集群汇总（summary）同样包含上述全部字段
    → summary.cpu.allocation  = 所有集群 CPU 分配成本之和
    → summary.cpu.usage       = 所有集群 CPU 使用成本之和
    → summary.cpu.idle        = 所有集群 CPU 空闲成本之和
    → summary.ram.allocation  = 所有集群 RAM 分配成本之和
    → summary.ram.idle        = 所有集群 RAM 空闲成本之和
    ```
    → **等价关系：** `totalAllocationCost = totalUsageCost + totalIdleCost`
    → **前端取值示例（所有集群合计）：**
      ```typescript
      const data = res.data.sets[0].summary;

      data.cpu.allocation  // CPU 分配成本合计
      data.cpu.usage       // CPU 使用成本合计
      data.cpu.idle        // CPU 空闲成本合计

      data.ram.allocation  // 内存分配成本合计
      data.ram.usage       // 内存使用成本合计
      data.ram.idle        // 内存空闲成本合计

      data.totalUsageCost       // 总使用成本
      data.totalAllocationCost    // 总分配成本
      data.totalIdleCost   // 总空闲成本
      data.efficiency      // 综合效率
      ```


- **集群成本趋势，默认展示近 7 天数据（折线图）**
  → `GET /kapis/costwise.wiztelemetry.io/v1alpha1/allocation?window=7d&aggregate=cluster&step=1d`
  → 字段：随时间片数组，每个元素取 `.data[i]["host"].totalCost`

- **按天展示总成本**

### 效率分析区域

- **集群效率：分为 CPU、内存、存储三类**
  → 推荐接口：`GET /kapis/costwise.wiztelemetry.io/v1alpha1/efficiency/clusters?window=7d&accumulate=true`
  → 兼容旧路径：`/efficiency/clusters/summary`
  → 集群字段：`.data.sets[0].clusters[clusterName].cpuEfficiency`、`.ramEfficiency`、`.efficiency`

- **页面口径效率计算公式（新接口已按此返回）：**
  ```
  cpuEff = clamp(cpuCoreUsageAverage / cpuCoreRequestAverage, 0, 1)
  ramEff = clamp(ramByteUsageAverage / ramByteRequestAverage, 0, 1)
  gpuEff = clamp(gpuUsageAverage / gpuRequestAverage, 0, 1)

  usageCost =
    cpuEff * (cpuCost - cpuCostIdle) +
    ramEff * (ramCost - ramCostIdle) +
    gpuEff * (gpuCost - gpuCostIdle)

  resourceCost = cpuCost + ramCost + gpuCost

  clusterEfficiency = usageCost / resourceCost
  ```
  → `cpuCostIdle` / `ramCostIdle` / `gpuCostIdle` 表示基础设施 idle 分摊到该聚合项上的成本
  → `pvCost`、`networkCost`、`loadBalancerCost`、`sharedCost`、`externalCost` **不参与效率计算**
  → **实测示例（cluster-one，近 7 天）：**
    ```
    cpuCoreRequestAverage = 3.816579908675804
    cpuCoreUsageAverage   = 0.5825583921284344
    cpuEff                = 0.15263885627133592

    ramByteRequestAverage = 10556318631.159817
    ramByteUsageAverage   = 15459306247.412035
    ramEff                = 1

    usageCost             = 13.13644664915174
    resourceCost          = 63.87889743619523
    clusterEfficiency     = 0.20564610812628603 (20.56%)
    ```
  → **注意：** 旧接口里的 `.totalEfficiency` / `.efficiency` 与页面口径不同，页面和新接口都不要直接使用它们
  → **注意：** 使用量可能超过申请量，显示时需封顶 `100%`

- **多集群场景：综合效率怎么算？**
  → 不能简单平均每个集群效率
  → 正确方式：先汇总 `usageCost` 和 `resourceCost`
    ```
    multiClusterEfficiency = Σ(usageCost) / Σ(resourceCost)
    ```
  → **不要用简单平均：** `avg(clusterEfficiency)` ❌

- **Idle 拆分：workload idle / infra idle / total idle**
  → 新接口建议直接返回这三个字段；若使用原始 summary 响应，也可按下述公式计算
  → **当前实际情况：** `cpuCostIdle` / `ramCostIdle` / `gpuCostIdle` 均为 0（后端未启用 SplitIdle）。
    因此 infraIdleCost = 0，totalIdleCost = workloadIdleCost。以下公式保留完整形态以作参考：
  ```
  workloadIdleCost =
    (1 - cpuEff) * (cpuCost - cpuCostIdle) +
    (1 - ramEff) * (ramCost - ramCostIdle) +
    (1 - gpuEff) * (gpuCost - gpuCostIdle)

  infraIdleCost =
    cpuCostIdle + ramCostIdle + gpuCostIdle

  totalIdleCost =
    workloadIdleCost + infraIdleCost
  ```
  → 含义：
    `workload idle` = 已分配给 workload、但 workload 没用满的成本
    `infra idle` = 集群/节点资产侧存在、尚未被 workload 有效消化的 idle 成本
    `total idle` = 二者之和
  → **cluster-one 样例（可由以下响应直接计算）：**
    ```
    cpuCost     = 50.64082199999984
    cpuCostIdle = 32.18808688382754
    ramCost     = 13.238075436195397
    ramCostIdle = 2.9182331702541133
    gpuCost     = 0
    gpuCostIdle = 0

    cpuEff            = 0.15263885627133592
    ramEff            = 1
    gpuEff            = 0
    usageCost         = 13.13644664915174
    workloadIdleCost  = 15.636130732961844
    infraIdleCost     = 35.10632005408165
    totalIdleCost     = 50.742450787043495
    resourceCost      = 63.87889743619523
    ```
  → 等价关系：
    `totalAllocationCost = totalUsageCost + workloadIdleCost + infraIdleCost`
  → **新接口实际返回字段（每个集群）：**
    `cpuEfficiency`、`ramEfficiency`、`gpuEfficiency`、
    `totalUsageCost`、`workloadIdleCost`、`infraIdleCost`、`totalIdleCost`、
    `totalAllocationCost`、`efficiency`
    `cpu.allocation` / `cpu.usage` / `cpu.idle` / `cpu.efficiency`
    `ram.allocation` / `ram.usage` / `ram.idle` / `ram.efficiency`
    `gpu.allocation` / `gpu.usage` / `gpu.idle` / `gpu.efficiency`
    `pv.allocation` / `pv.usage` / `pv.idle` / `pv.efficiency`
  → **新接口实际返回 summary：**
    包含上述所有字段的多集群合计值：
    `summary.totalUsageCost`、`summary.totalAllocationCost`、`summary.totalIdleCost`、`summary.efficiency`
    `summary.cpu.allocation`、`summary.cpu.usage`、`summary.cpu.idle`、`summary.cpu.efficiency`
    `summary.ram.allocation`、`summary.ram.usage`、`summary.ram.idle`、`summary.ram.efficiency`
    `summary.gpu.allocation`、`summary.gpu.usage`、`summary.gpu.idle`、`summary.gpu.efficiency`
    `summary.pv.allocation`、`summary.pv.usage`、`summary.pv.idle`、`summary.pv.efficiency`

- **展示当前窗口的效率数值（百分比）**
  → 新接口：`.data.sets[0].summary.efficiency × 100`

## 资产原始数据查询 — /assets 端点

> 当需要通过资产类型（节点/磁盘/LB 等）精确过滤原始资产数据时，使用此端点。

### 接口地址

```
GET /kapis/costwise.wiztelemetry.io/v1alpha1/assets?window=<时间窗口>&filter=<过滤条件>
```

### 按类型查询示例

> **⚠️ filter 语法注意事项：**
> - 条件之间用 **`+`** 连接表示 AND，如 `cluster:"host"+assetType:"node"`
> - 同一字段多个值用 **`,`** 分隔表示 OR，如 `assetType:"node","disk"`
> - `assetType` 字段值必须使用**小写**，如 `assetType:"node"` 而非 `assetType:"Node"`
> - 其他字段（`cluster`、`name` 等）按实际值匹配，大小写敏感

**查询全部资产（不区分类型）**
```
GET /kapis/costwise.wiztelemetry.io/v1alpha1/assets?window=7d
```
返回所有类型资产（Node、Disk、LoadBalancer、Cloud、Network 等）的完整列表，按资产 key 组织在 `assets` 对象中。

**只查节点资产**
```
GET /kapis/costwise.wiztelemetry.io/v1alpha1/assets?window=7d&filter=assetType:"node"
```
返回所有集群的节点资产。

**只查存储资产（PV/Disk）**
```
GET /kapis/costwise.wiztelemetry.io/v1alpha1/assets?window=7d&filter=assetType:"disk"
```
返回所有集群的磁盘资产。

**只查负载均衡器**
```
GET /kapis/costwise.wiztelemetry.io/v1alpha1/assets?window=7d&filter=assetType:"loadbalancer"
```

**查单个集群的全部资产**
```
GET /kapis/costwise.wiztelemetry.io/v1alpha1/assets?window=7d&filter=cluster:"host"
```
不传 `assetType` 时返回该集群下所有类型资产。

**查单个集群的节点资产**
```
GET /kapis/costwise.wiztelemetry.io/v1alpha1/assets?window=7d&filter=cluster:"host"+assetType:"node"
```

**查单个集群的存储资产**
```
GET /kapis/costwise.wiztelemetry.io/v1alpha1/assets?window=7d&filter=cluster:"host"+assetType:"disk"
```

### 资产图表接口（/assets/graph）使用说明

> **⚠️ URL 编码注意事项：**
> - `filter` 中的 **`+`** 表示 AND，但放在 URL 里必须编码成 **`%2B`**
> - 如果直接写 `filter=assetType:"disk"+name:"pvc-xxx"`，后端通常会把 `+` 解码成空格，导致解析报错
> - 建议统一写成：`filter=assetType:"disk"%2Bname:"pvc-xxx"`

### /assets/graph 常用参数

- `window`
  → 时间窗口，例如 `1d`、`7d`
- `aggregate`
  → 图表分组维度，常用：`type`、`name`、`cluster`、`service`
- `filter`
  → 资产过滤条件，先过滤再聚合
- `accumulate`
  → 时间粒度，常用：`day`、`week`、`month`
- `limit`
  → 每个时间片返回的最大图表项数量
- `offset`
  → 每个时间片图表项偏移量

| 对比项 | `/allocation` | `/assets` |

| 适用场景 | 成本分摊分析、按工作负载查看 | 查看底层资源详情、资产清单 |

  → `window=<ISO起始时间>,<ISO结束时间>`
  → 示例：`window=2026-05-01T00:00:00Z,2026-05-12T00:00:00Z`

  → `step=1d` 按天拆分
  → 不加 `step` 时按整个窗口聚合（默认）

### 筛选过滤

- **按集群筛选**
  → `filter=cluster:"<集群名>"`

- **按命名空间/项目筛选**
  → `filter=namespace:"<命名空间>"`

- **按企业空间筛选**
  → API filter 不支持 `namespaceLabels`、`label:kubesphere.io/workspace`

## API 局限性与缺失项

以下功能点在当前 API 中存在字段缺失或不支持：

| 功能点 | 当前状态 |
|--------|----------|
| **存储类型**（SSD/HDD） | API 无此信息 |
| **Pod 状态**（Running/Pending） | API 无此信息 |
| **PV→Pod 关联映射** | API 无此信息 |
| **服务类型**（ClusterIP/NodePort/LB） | API 无此信息 |
| **节点资源总量**（非分配量） | API 无此信息 |
| **Pod 副本数** | API 无此信息，需外部获取 |
| **搜索/分页** | API 不支持，需前端实现 |
| **按企业空间筛选**（namespaceLabels 过滤） | filter 语法不支持，需前端过滤 |
| **按 deployment/controller/service/label 筛选** | filter 不支持这些字段，仅支持 cluster/namespace/node/pod/container |
| **空闲成本**（cpuCostIdle/ramCostIdle） | 当前始终返回 0。原因是后端 `ComputeAllocation` 未启用 `SplitIdle`，idle allocations 保持为独立条目（`__idle__`），未被拆入各资源的 idle 字段。替代方案：使用 `/efficiency/clusters` 返回的 `totalUsageCost`/`workloadIdleCost`/`totalIdleCost`，它们通过 `efficiency × cost` 口径计算，不依赖 `cpuCostIdle` |
| **存储已使用量** | API 无此信息，仅提供容量 |
